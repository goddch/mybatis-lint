# SQL プレビュー

mapper XML の statement を、MyBatis のタグを取り除いた SQL として表示する機能です。
Markdown のプレビューと同じように、エディタの横にパネルを開きます。

## 開き方

- mapper XML のエディタで **Ctrl+Shift+V**(Mac は Cmd+Shift+V)
- エディタ右上のプレビューのボタン
- コマンドパレットの **MyBatis Lint: Show SQL Preview**

カーソルがある `<select>` / `<insert>` / `<update>` / `<delete>` を表示します。カーソルを別の
statement に移すと、表示も切り替わります。編集すると、保存しなくても表示が変わります。

## 分岐の切り替え

パネルで分岐を選びます。「Pick branches from values」をオンにすると、入力した値で `test` の条件を
評価して、決まる分岐は自動で選びます(下の「値から分岐を選ぶ」)。

| タグ | パネルでの操作 | 既定 |
|---|---|---|
| `<if>` | チェックボックスでオン・オフ | オン |
| `<choose>` | どの `<when>` / `<otherwise>` を使うか | 最初の `<when>` |
| `<foreach>` | 繰り返す回数(0〜20) | 2 回(区切り文字が見えるように) |

入れ子の分岐は字下げして表示します。外側の `<if>` をオフにすると、内側の分岐は表示されません。

MyBatis と同じ規則で、次のタグも組み立てます。

- `<where>`:先頭の `AND` / `OR` を取り除き、中身がなければ `WHERE` ごと出さない
- `<set>`:先頭と末尾のカンマを取り除く
- `<trim>`:`prefix` / `prefixOverrides` / `suffix` / `suffixOverrides` のとおりにする
- `<include>`:別ファイルの `<sql>` も展開し、`<property>` の値を `${...}` に入れる
- `<foreach>`:`#{item}` / `#{item.name}` は `:ids_0` / `:users_0_name` のように何回目かがわかる名前にし、
  `#{index}` は回数の数字にする
- `<bind>` は変数を定義するだけなので、SQL には何も出さない(その変数を使う `#{...}` はパラメータのまま)。
  `<selectKey>` は別の SQL として実行されるので表示しない

## 値から分岐を選ぶ

「Pick branches from values」をオンにすると、パラメータの入力欄に入れた値で `<if>` / `<when>` の
`test` を評価します。条件だけで使う名前(`#{...}` には出てこないもの)にも入力欄を出します(`(test)` と表示)。

- 値は SQL と同じ書き方で入れます:`'abc'`(文字列)、`123`、`NULL`、`true` / `false`
- `ids.size() > 0` のようなコレクションの大きさは、その `<foreach>` の繰り返し回数を使います
- 決まった分岐は「(from values)」と表示され、手で切り替えられなくなります。値が入っていない、
  対応していない式(`name.matches(...)` など)を使っている、などで決まらない分岐は、手で選んだものを使います
- `<choose>` は、上の `<when>` から順に評価し、最初に成り立つものを使います。途中に決まらない `<when>` が
  あれば、手で選んだものを使います

評価は OGNL(MyBatis が使う式の言語)に合わせているので、MyBatis のよくある落とし穴もそのまま再現します。

- `type == 'A'` の `'A'` は 1 文字なので char になり、String の `"A"` とは等しくなりません。`'A'` を入力しても
  この `<when>` は選ばれません(`single-char-literal-comparison` が警告するもの)
- 数値と `''` を比べると、`''` は 0 として扱われます。`status` に `0` を入れると `status != ''` は false になります
  (`numeric-empty-string-comparison` が警告するもの)

対応している式:`==` / `!=` / `<` / `>` / `<=` / `>=`(`eq` / `neq` / `lt` / `gt` / `lte` / `gte` も)、`and` / `or` / `not`
(`&&` / `||` / `!` も)、括弧、`null` / `true` / `false`、数値、文字列、`.size()` / `.length()` / `.isEmpty()` / `.trim()`。
`<foreach>` の中の `item` / `index` を使う条件は評価しません。

## パラメータの書き方

| 選択肢 | `#{userName}` の出力 | 使い方 |
|---|---|---|
| `:name`(既定) | `:userName` | DBeaver などに貼り付けて実行すると、値を入力する画面が出る |
| `?` | `?` | JDBC と同じ形 |
| typed values | パネルで入力した値(`'abc'`、`123`、`DATE '2026-01-31'` など。未入力なら `:userName`) | そのまま実行できる SQL にする |

`user.name` のような名前は `:user_name` にします(多くの SQL クライアントは名前に `.` を使えないため)。

`${...}` は値が SQL にそのまま入るので、どの選択肢でもパネルに入力欄を出し、入力した文字列を
そのまま埋め込みます。入力しなければ `${...}` のまま残ります。

**Copy SQL** で、表示している SQL をクリップボードにコピーします。

## できないこと

- `test` の条件のうち、メソッドの呼び出し(`.size()` などを除く)や Java の定数を使うものの評価
- `@SelectProvider` など、Java で組み立てる SQL
- 表示は MyBatis の組み立て方に合わせていますが、空白や改行は読みやすいように整えています
  (句の始まり(`SELECT`、`FROM`、`WHERE` など)は行頭、そのほかの行は 2 文字下げ)。文字列リテラルの中の空白は変えません
